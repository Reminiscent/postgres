FILE: src/backend/commands/subscriptioncmds.c
FUNCTION: AlterSubscription (SUBOPT_TWOPHASE_COMMIT branch)
DEFECT: The "prepared transactions exist" check for disabling two_phase is gated on sub->twophasestate == ENABLED. But SET (two_phase=on) on an already ENABLED sub rewrites the state to PENDING (slot still two_phase=true, prepared xacts may still exist on the subscriber). A following SET (two_phase=off) sees PENDING, skips LookupGXactBySubid, and turns the slot option off.
FAILURE: ENABLED sub with pending prepared txns -> ALTER SET(two_phase=on) -> ALTER SET(two_phase=off) succeeds; COMMIT PREPARED later arrives with the full txn re-sent (slot no longer two_phase), giving duplicate data or errors.
RULE: Slot two_phase may be turned off only if no prepared transactions of the subscription remain, regardless of the catalog tri-state (and ENABLED->true should not downgrade state to PENDING).
