PostgreSQL once changed snapshot export and import so that the exporting session no longer needs an assigned transaction id: the export file records the virtual transaction id, which avoids serializing logical-slot creation and also makes it possible to export snapshots on hot-standby replicas. On a standby, a snapshot lists in-progress transactions differently from a primary: all running top-level and sub transaction ids are stored in the sub-transaction array, with the top-level array left empty, and the overflow flag does not mean what it means elsewhere.
