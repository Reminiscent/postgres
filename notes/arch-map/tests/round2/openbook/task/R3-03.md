A recent feature let autovacuum workers use parallel workers for index vacuuming and cleanup, controlled by a new GUC and a per-table storage parameter. To handle a SIGHUP changing cost-based delay settings mid-operation, the leader stores its effective cost parameters in dynamic shared memory, and parallel workers poll for updates. Setup of this sharing happens when the parallel context is created and registers a cleanup callback to run when the shared memory segment is detached.
