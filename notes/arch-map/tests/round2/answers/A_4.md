ANSWER: With EXEC_BACKEND each child re-executes the binary and must re-attach to shared state; the new callback-based API attaches via per-process callbacks. wal_debug builds (WAL_DEBUG) allocate a debug-only per-process xlog_debug memory context / static buffer in the old shmem-init path, which the conversion skipped for the attach path in child processes. Violated: child processes must see the same initialized shared/process state as the postmaster (consistent attach).
