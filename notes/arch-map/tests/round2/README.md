## 开卷试跑

做法：从 26 道风险题里按固定种子抽 8 道；用 `git archive` 取出修复提交的父提交的 `src/backend` 和 `src/include`（没有 git 历史）；
告诉读者"下面这个改动已经在代码里，后来发现它有一处缺陷，请找出来"，最多 30 次工具调用，给出至多 3 个候选。读者是 sonnet。

- R3-02 第一次跑时，"带地图"的读者根本没读地图；表里用的是重跑的那一份。

## 局限

- 开卷只有 8 题、一种模型、一种任务形式（事后找一个已知存在的缺陷），区间很宽；"地图更差"不能下结论，"地图没有显示出增益、并且更贵"可以。
- 题目是"后来被修掉的疏漏"，这类缺陷多数是局部的。地图针对的是非局部的情形：改动破坏了远处代码依赖的假设。这类题没有专门抽。
- 没有测的用途：动手之前的设计评审（代码还不存在）；人类读者；更弱或 token 预算更紧的读者。
- 地图建在这些提交之后；评分员能从措辞看出条件。

`openbook/`（任务、答卷、评分）。代码快照没有入库，可用 `git archive <修复提交>^ src/backend src/include` 重建。
