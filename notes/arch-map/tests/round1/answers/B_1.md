## B1-02
FILES: src/backend/postmaster/postmaster.c
ANSWER: Shutdown is orchestrated by the postmaster state machine, which already owns the "who is signalled with what, and when the SIGKILL escalation timer starts" logic for all child types. Signalling each child directly from the shutdown code would bypass that machinery (per-child-type handling, timer reset, state transitions) and duplicate it; also a freshly forked child may not have installed its handlers yet, so SIGTERM is ignored whereas the immediate-stop path (SIGQUIT, with the SIGKILL timer) is the one that already works in that window. So reuse the existing immediate-stop path when the crash flag (FatalError) is set.
CONFIDENCE: high for (a); medium for (b)
DRILL: read PostmasterStateMachine / pmdie in postmaster.c and the commit message of the fix.
