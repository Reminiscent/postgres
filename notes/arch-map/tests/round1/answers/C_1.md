## B1-02
FILES: postmaster/postmaster.c
ANSWER: The fix changes pmdie() for SIGTERM/SIGINT so that when FatalError (the crash flag) is set, the shutdown sends the immediate-stop signal (SIGQUIT) to all children through the existing state-machine path. It does not send SIGTERM. Signalling children one by one was not chosen because the postmaster has one central signalling and timeout machinery (PM state machine, SIGQUIT then SIGKILL after the abort timer), which the crash path already relies on. Freshly forked children may not have installed their handlers yet or still ignore SIGTERM, whereas SIGQUIT is handled by default or immediately. Per-child signalling would duplicate the state logic and could miss children still starting.
CONFIDENCE: high for (a); medium for (b)
DRILL: Read pmdie() and HandleChildCrash()/PostmasterStateMachine() in postmaster.c, and which signal each child type handles at startup.

## B1-03
FILES: postmaster/postmaster.c
ANSWER: The fix is in postmaster.c, in the child-exit handling for the startup process, i.e. process_pm_child_exit or HandleChildCrash. The startup-process crash must be handled even when FatalError is already set, so that pmState advances to PM_WAIT_BACKENDS/dead-end and the postmaster exits. It must still run the general cleanup that signals the other children, because the earlier shortcut orphaned them. The early return on FatalError exists to avoid repeating the SIGQUIT broadcast, so the fix lets the startup-crash case bypass it instead of restoring the shortcut. S01.M01 Inv(5) says a startup crash exits the postmaster rather than resetting.
CONFIDENCE: high for (a); medium for (b)
DRILL: Read the startup-exit branch of process_pm_child_exit and the FatalError early return in HandleChildCrash (postmaster.c, around the file:3238-3251 lines the map cites).

## B1-04

## B1-05
FILES: tcop/backend_startup.c, storage/ipc/procsignal.c, postmaster/postmaster.c, storage/ipc/pmsignal.c, storage/lmgr/proc.c
ANSWER: The original change made the pre-auth process touch shared memory, taking the ProcSignal slot spinlock and comparing cancel keys. Such a process has no PGPROC, is not marked ACTIVE in PMChildFlags (the dead-man switch), and has no cleanup. It can be killed by authentication_timeout, SIGTERM or a _exit(1) at that point. Then a spinlock may be left held, the postmaster does not learn it touched shared memory, and a crash there is not detected. This violates S01.M01 Inv(1)/(2) and S02.M01 Inv(1)/(2): processes that touch shared memory must register for crash detection and must not exit uncleanly while holding shared state. The fix would keep the cancel path to the safe shared-memory protocol and ordering, possibly also signal timeouts and PMChildFlags handling.
CONFIDENCE: medium for (a); medium for (b)
DRILL: Read the cancel-request path in backend_startup.c (the map cites file:382-388), SendCancelRequest and the cancel-key compare in procsignal.c, and PMChildFlags setup in pmsignal.c.

## B1-06
FILES: libpq/be-secure-openssl.c, libpq/hba.c, tcop/backend_startup.c, libpq/be-secure.c, utils/init/postinit.c
ANSWER: The fix is in the OpenSSL initialisation, be_tls_init, which loads the hosts file. A failing SNI host entry no longer discards the whole configuration. The default context and the hosts that load successfully are kept, and the bad entry is logged and skipped (or only that host is dropped). The constraint is that in EXEC_BACKEND and Windows children there is no earlier valid configuration to fall back on, because the postmaster's loaded config is not inherited. Postmaster reload can keep the old context on failure, but a child cannot (S02.M01 Contract: SSL is re-initialised in the child, and on failure SSL is not used).

DRILL: Read be_tls_init and its host-list loading in be-secure-openssl.c, and the SSL init in backend_startup.c (the map cites file:95-118).

## B1-07
FILES: libpq/auth-oauth.c
ANSWER: The fix is in the GUC check hook for oauth_validator_libraries, in auth-oauth.c. It validates the parsed result of the list-splitting call, for example by testing for an empty list (or list_length) afterwards. It does not add a special case for the whitespace-only string before parsing. A string-level special case covers only the forms the author thought of, such as the empty string. It misses other inputs that parse to nothing, such as a whitespace-only string or separators only. The parser's output (the list) is the authoritative definition of a valid or empty setting, so checking it handles every such input. It also prevents the invalid state (a NIL or garbage list element used later) that crashed the postmaster on reload.
CONFIDENCE: medium for (a); medium for (b)
DRILL: Read check_oauth_validator_libraries and its SplitDirectoryString/SplitIdentifierString usage in auth-oauth.c.

## B1-08
FILES: utils/cache/funccache.c
ANSWER: The fix is in funccache.c, in key construction (compute_function_hashkey). In validation mode the result-type resolution is skipped, or made tolerant, when the call info is the stripped-down validation descriptor (no flinfo/expr/resultinfo). The key then falls back to a result type that is not resolved, so the polymorphism check can run and produce the PL's own clear message. The constraint is that the other languages' callers and the key format must not change, and the validator's dummy fcinfo cannot be made richer for the cache's sake. So the cache code guards itself, in line with S02.M06, where funccache keys on the pg_proc xmin and tid.
CONFIDENCE: medium for (a); medium for (b)
DRILL: Read compute_function_hashkey and its use of get_call_result_type in funccache.c, and the PL/Python validator call path.

## B1-10
FILES: utils/adt/ri_triggers.c
ANSWER: The metadata (the cached comparison functions and similar, kept for the referenced index) was cached in the RI constraint cache entry. When invalidation arrived it was marked invalid but its memory was not released. Each re-validation allocated again, so memory leaked across invalidations. The follow-up work addresses the fact that freeing it eagerly in the callback is unsafe if the callback fires while the entry is in use (see B1-11). The correctness property is resource lifecycle (I5): the cache entry's lifetime must be tied to its owner or to a refcount, and free must happen only when no check is running (I4, cache consistency under invalidation).
CONFIDENCE: medium for (a); low for (b)
DRILL: Read InvalidateConstraintCacheCallBack and ri_LoadConstraintInfo and the fast-path cache struct in ri_triggers.c.

## B1-11
FILES: utils/adt/ri_triggers.c, utils/cache/plancache.c, executor/spi.c
ANSWER: The fix is in ri_triggers.c. The cached plan or entry used by a check must not be freed or replaced while it is executing, because user code run during the check can trigger a nested check and a plan invalidation. The check therefore takes a stable reference. Candidates are a refcount or pin on the entry or plan, a private copy, or deferring the free until the outermost use ends, so that a nested call cannot free or rebuild what the outer call still uses. The reasoning is re-entrancy plus plancache lazy invalidation (D-plancache-lazy-inval): invalidation only marks the plan, and the next use rebuilds it. The cache-clobbering build makes the invalidation deterministic and exposes the dangling pointer.
CONFIDENCE: high for (a); medium for (b)
DRILL: Read ri_PerformCheck, ri_FetchConstraintInfo and the SPI plan caching and invalidation in ri_triggers.c, and the plan reference rules in plancache.c.

## B1-12
FILES: utils/mmgr/aset.c
ANSWER: The fix is in AllocSetContextCreateInternal in aset.c. When a context is taken from the freelist for reuse, its size-dependent fields must be recomputed from the new caller's parameters, or the freelist must match on them. Those fields are maxBlockSize, initBlockSize, nextBlockSize and allocChunkLimit. A recycled context keeps the old max-block-size-derived allocChunkLimit, so allocations go onto dedicated blocks (excess malloc) or pfree does not return memory until reset. The constraint is that freelist slots are keyed by a coarse size class, so contexts with different maxBlockSize share a slot. Reuse must therefore reinitialise those fields (or check them) and must not assume identical parameters.
CONFIDENCE: high for (a); medium for (b)
DRILL: Read the freelist reuse branch and allocChunkLimit computation in AllocSetContextCreateInternal in aset.c.
