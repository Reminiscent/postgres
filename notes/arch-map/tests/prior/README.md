# 逐条规则的先验测试：模型不看材料时已经知道多少

日期 2026-11-13。对象：`invariants/I1..I8.md` §3 的 150 条规则（I1.R26 漏评，实际 149 条）。

## 结论

模型读者不看任何材料，就已经知道这些规则的绝大部分。

| 模型 | 平均得分 | 全部要点答到 | 答到一部分 | 没答到 | 断言与规则相反 |
|---|---|---|---|---|---|
| haiku | 0.78 | 57 | 82 | 10 | 5 |
| sonnet | 0.85 | 73 | 71 | 5 | 2 |
| opus | 0.91 | 104 | 43 | 2 | 0 |

按要点算（每条规则拆成 2–3 个原子要点，共 409 个）：完全没答到的，haiku 54 个、sonnet 34 个、opus 23 个；**三档都没答到的只有 22 个**，列在 `../../model-delta.md`。

按族看 opus 的得分：I3 0.96、I8 0.94、I1 0.92、I5 0.92、I6 0.92、I7 0.90、I2 0.88、I4 0.83。最弱的是缓存一致性和可见性。
opus 整条没答到的规则只有两条：I2.R3（不是从进行中事务表取得的快照）和 I4.R11（弱锁 DDL 下分区集合在规划与执行之间会变）。

## 这说明什么

- 前两轮检验里地图和 `invariants/` 没有带来提升，原因在这里：里面九成以上的内容，模型读者本来就知道。
- 对模型读者，值得给的不是知识的全集，而是它不知道的那一小部分。
- 模型"被问到时知道"和"干活时想得起来、并去对照代码"是两回事。前两轮检验里答错的题，多数不是因为不知道规则。

## 方法和局限

- 出题：每条规则一道情境题，题面不含答案（`GEN.md`）；读者不看任何材料作答（`READER.md`）；评分员看不到是哪档模型，逐个要点给 0 / 0.5 / 1（`GRADER.md`）。
- 题面会提示情境（提到相关的操作和场合），所以测到的是有提示时的回忆，偏向高估。
- 约三分之一的规则是复合的（出题者标出 33 条），一道题问不全；"答到一部分"里有一部分是题目没问到，不是模型不知道。
- 评分没有复核；0.5 分的判定偏宽。
- 这些规则大多是长期存在的。训练截止之后才出现的子系统（比如异步 I/O）里的规则，模型知道得会少，这里没有单独统计。

## 材料

`questions/`（题、答案、要点）、`answers/`（三档模型各四份答卷）、`grades/`（评分、标签对照、逐条汇总 `rec.json`）、`build.py`。
