# S03 查询前端（Tier S）
Secret: SQL 文本如何变成带 OID、类型、锁模式的 Query 树，以及视图、规则、RLS 如何以树变换展开。
边界: `parser/gram.y` `parser/scan.l` 非 .c，生成物属 [[S03.M01]]；`commands/policy.c`（pg_policy DDL 与 relcache 策略描述）[[S11.M15]]；
`utils/adt/ruleutils.c`（反解析，调用 AcquireRewriteLocks）[[S12]]；`utils/cache/plancache.c`（重分析、重改写）[[S02.M06]]；
`utils/misc/queryenvironment.c` [[S05]]；`tcop/postgres.c` 驱动 parse→analyze→rewrite [[S01]]。

## 设计原因（决策）
- D-raw-parse-no-catalog {[[F1]]} 原始解析与语义分析分两步，语法不许访问表 ← 原始: 未考证；当前: 必须能在已中止的事务里做基本解析（如识别 ROLLBACK）〔file:src/backend/parser/parser.c:6-10〕
- D-analyze-takes-locks {[[F1]] [[F2]]} 可优化语句在分析时就取锁并完成全部语义分析（[[I3]]） ← 原始: 未考证；当前: 后续模块保留或重取这些锁后才依赖分析结果；锁在首次打开关系时取得，模式记入 RTE〔file:src/backend/parser/analyze.c:6-9; file:src/backend/parser/parse_relation.c:1535-1544〕
- D-utility-late-analysis {[[F1]]} utility 语句不在分析期变换，推迟到执行开始 ← 原始与当前: querytree 可能被缓存，而 utility 语句既不持锁也没有重验证机制，分析时依赖的 catalog 状态到执行时可能已过期（[[I4]]）〔file:src/backend/parser/parse_utilcmd.c:6-12; file:src/backend/parser/analyze.c:10-14; commit:46379d6e60f〕
- D-rewrite-relock {[[F1]] [[F2]]} 改写阶段对来自存储规则或缓存的树重新取锁（AcquireRewriteLocks） ← 原始: 把规则所引关系的取锁移到独立函数，常规路径省去解析器与改写器的重复取锁，并明确在任何基于关系属性的改写决定前取锁；同时以线性时间修正 JOIN 别名中的已删除列〔commit:ba42002461a〕；当前: 处理早于当前命令产生的树时必须做，刚由解析器建好的树可以也应当跳过，因为分析期已取得同样的锁、也不会在 JOIN 中包含已删除列（[[I3]]）〔file:src/backend/rewrite/rewriteHandler.c:103-131,4678-4680; file:src/backend/utils/cache/plancache.c:850〕；陷阱: 它会就地修改 querytree，调用者通常应先 copyObject〔file:src/backend/rewrite/rewriteHandler.c:108-110〕；存储规则的 JOIN 别名可引用已删除列，依赖机制不阻止该列被删〔file:src/backend/rewrite/rewriteHandler.c:133-139〕
- D-view-rls-as-rewrite {[[F7]] [[F1]]} 视图与 RLS 都在改写期以 Query 树变换实现（RIR 展开、策略表达式前置到 securityQuals），COPY 等路径也构造普通查询复用之（[[I6]]） ← 原始: RLS 建在可更新 security-barrier 视图之上，过滤表达式加入 security barrier quals、检查表达式加入 with-check options〔commit:491c029dbc4〕；视图展开的原始理由未考证；当前: 所有返回或接收行的路径统一经过一处注入点〔file:src/backend/rewrite/rowsecurity.c:13-23〕；视图引用由 ON SELECT 规则展开为子查询 RTE〔file:src/backend/rewrite/rewriteHandler.c:1757,1891-1898,2033-2037〕；陷阱: RLS 表达式在分析之后注入，其中 SubLink 引用的关系须在注入后补取锁〔file:src/backend/rewrite/rewriteHandler.c:2290-2299〕；ON SELECT 规则不受 session_replication_role 抑制，视图在 REPLICA 角色下照常展开〔file:src/backend/rewrite/rewriteHandler.c:1714-1718〕；视图与策略的递归引用以 activeRIRs 检测并报错〔file:src/backend/rewrite/rewriteHandler.c:2176-2181,2282-2286〕
- D-rls-env-replan {[[F1]]} RLS 判定可依赖环境（角色、row_security），以 RLS_NONE_ENV/hasRowSecurity 标记交由 [[S02.M06]] 在环境变化时重做改写（[[I4]]） ← 原始: 未考证；当前: 即使本次不注入策略，判定结果也可能随角色或 row_security 改变〔file:src/backend/utils/misc/rls.c:31-40; file:src/backend/rewrite/rowsecurity.c:136-148〕；陷阱: 展开视图、子查询、CTE、SubLink 时必须把内层的 hasRowSecurity 并入外层 Query，计划缓存只从最终树提取 dependsOnRLS〔file:src/backend/rewrite/rewriteHandler.c:1885-1889,2019,2094,2214; file:src/backend/utils/cache/plancache.c:456-459〕
