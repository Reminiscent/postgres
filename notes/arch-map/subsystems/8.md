# S08 存储（Tier B）
Secret: 页在内存与磁盘之间怎样缓存、读写、刷盘、校验，以及关系物理文件怎样随事务创建和删除。
边界: `access/heap/visibilitymap.c` → [[S06]]；`postmaster/checkpointer.c` → [[S09]]（它吸收 fsync 请求队列，`ProcessSyncRequests` 由 `xlog.c` 在 checkpoint 中调用）；`access/transam/xlog.c` 的 `SetDataChecksumsOn/Off`（校验和状态落控制文件、写 WAL）→ [[S09]]；procsignal barrier → [[S01]]；`commands/dbcommands.c`（调用 `copydir`）→ [[S11]]。

## 设计原因（决策）
- D-own-buffer-cache {[[F1]] [[F6]]} 自有共享 buffer 缓存，写出交给内核 → 基础性决策，完整记录见 principles.md 的 [[D-own-buffer-cache]]
- D-clock-sweep {[[F4]]} 替换用 clock sweep ← 原始: 全局 freelist/LRU 链是多后端争用点，ARC/2Q/LRU 随之放弃，换成只需 buffer 头自旋锁的使用计数〔commit:5d5087363d7〕；当前: 算法见〔file:src/backend/storage/buffer/README:175-185〕，2025 年去掉 freelist，因其同步开销且妨碍后续补丁〔commit:2c789405275〕
- D-page-checksum {[[F1]]} FPW 之外还要页校验和 ← 原始: 未考证；当前: FPW 只防撕裂页，校验和检测 IO 系统造成的损坏；WAL CRC 保护进入 WAL 的记录，页校验和保护进入共享池的块〔file:src/backend/storage/page/README:6-10,31-39〕（另见 [[D-full-page-writes]]、[[D-hint-wal-checksum]]）
- D-fsm-no-wal {[[F4]]} FSM 不写 WAL ← 原始: 未考证；当前: 只是提示，靠页内自检重建与 VACUUM 重算自修复；但仍用 MarkBufferDirtyHint，因其他代码会校验 FSM 文件的校验和〔readme:src/backend/storage/freespace/README#Recovery〕
- D-smgr-layer {[[F7]] [[F3]]} 保留 smgr 分派层 ← 原始: 未考证（README 称源自 Berkeley 时代的多存储管理器）；当前: 为其他存储管理器留口，多一层函数调用相对 IO 可忽略；隐藏"一个关系=多 fork×多个 RELSEG_SIZE 段文件"〔file:src/backend/storage/smgr/README:6-17,40-44; file:src/backend/storage/smgr/md.c:46-52〕
- D-fsync-fail-panic {[[F1]]} fsync 失败即 PANIC ← 原始与当前: 部分 OS 写回失败后丢弃脏页，重试 fsync 可能假成功，唯一副本在 WAL〔commit:9ccdd7f66e3; file:src/backend/storage/file/fd.c:3970-3984〕
