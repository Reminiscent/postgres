## 设计原因（决策）
- D-path-plan-split {[[F4]]} 先枚举 Path 按代价淘汰，再生成 Plan → 基础性决策，完整记录见 principles.md 的 [[D-path-plan-split]]
- D-equivalence-class {[[F4]] [[F1]]} 用 EquivalenceClass 表示传递相等 ← 原始: 不完整 opfamily 下不再失败、避免生成再丢弃冗余等值子句、去掉派生等式必用"="的假设〔commit:f41803bb39b〕；当前: 推导原文没有的连接条件，避免被迫做笛卡尔积〔file:src/backend/optimizer/README:696-713〕
- D-pathkeys {[[F4]]} pathkeys = 某 Path 输出"已知的排序"，元素引用 EC 而非单个表达式 ← 原始: 识别冗余排序列、mergejoin 可用多种排序方向〔commit:f41803bb39b〕；当前: 按任一成员有序即按全部有序；canonical 化后可指针比较，add_path 比较代价低〔file:src/backend/optimizer/README:910-924,987-990〕
- D-geqo {[[F4]]} GEQO：连接数 ≥ geqo_threshold 时半随机搜索连接顺序，每个连接对仍交给 /path 生成全部实现路径 ← 原始: 未考证；当前: 半随机搜索代替穷举全部连接树〔file:src/backend/optimizer/README:10-14; file:src/backend/optimizer/path/allpaths.c:3924〕；假设: 穷举 DP 随连接数爆炸
- D-var-nullingrels {[[F1]] [[F7]]} Var 携带 varnullingrels ← 原始: 否则 equal() 的表达式在外连接上下可能不是同一个值，是规划器的正确性隐患；代价是 FDW 的外部连接规划必须跟着改〔commit:2489d76c490〕；当前: 据此判断表达式能否在外连接下方求值〔file:src/backend/optimizer/README:343-357〕
- D-extended-stats {[[F4]]} 扩展统计与统计导入 ← 原始: 关系级与属性级统计导入函数供 pg_dump 调用，升级后免跑 ANALYZE〔commit:d32d1463995〕；扩展统计本身未考证；当前: 默认估计做法依赖独立性假设，实践中常不成立并造成估计错误〔file:src/backend/statistics/README:4-6〕
