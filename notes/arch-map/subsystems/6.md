## 设计原因（决策）
- D-mvcc-no-overwrite {[[F2]]} 不立即移除行的旧版本，由 VACUUM 回收 → 基础性决策，完整记录见 principles.md 的 [[D-mvcc-no-overwrite]]
- D-xid-wraparound-freeze {[[F1]] [[F5]]} 32 位 XID 取模比较，靠 freeze 防回卷 → 基础性决策，完整记录见 principles.md 的 [[D-xid-wraparound-freeze]]
- D-hot {[[F4]]} HOT：同页且不改索引列时不建新索引项，可单页回收 ← 原始: 未考证；当前: 普通 vacuum 必须扫索引，重算索引键又依赖可能不 immutable 的用户函数；约束是同页、按二进制比较索引列〔file:src/backend/access/heap/README.HOT:15-33,113-122,136-148〕
- D-idx-am {[[F3]] [[F1]]} index AM 能力从 pg_am 列改为 handler 返回的 C 结构体 ← 原始: 编译器可检查签名、扩展可定义 AM；代价是 SQL 层 opr_sanity 交叉检查失效，以 amvalidate 补偿〔commit:65c5fcd353a〕
- D-table-am {[[F3]]} 引入 table AM，表存储经 handler 结构体回调（CREATE TABLE ... USING），沿用 index AM 模式，结构体需与后端同寿 ← 原始: 提交说明引入 CREATE ACCESS METHOD ... TYPE TABLE 与 CREATE TABLE ... USING，规格仿 index AM，结构体须与后端同寿，未另写动机〔commit:8586bf7ed88〕；当前: 结构体须以服务器生命周期分配，经 table_* 包装调用〔file:src/include/access/tableam.h:311-320〕
- D-repack-concurrently {[[F2]]} REPACK CONCURRENTLY 用逻辑解码捕获复制期间的并发变更，只在交换 relfilenode 时取 AccessExclusiveLock ← 原始与当前: 初始复制只持 ShareUpdateExclusiveLock，应用可正常访问原表直到交换前，缩短强锁持有时间〔commit:28d534e2ae0; file:src/backend/commands/repack.c:7-21〕
