## 设计原因（决策）
- D-abort-by-clog {[[F4]] [[F1]]} 中止只在 clog 记一笔，且不刷 WAL；崩溃时在途事务靠排除法判为中止 ← 原始: 未考证；当前: 崩溃后本来就默认视为中止，所以中止记录不必刷盘、也不必与 checkpoint 互锁〔file:src/backend/access/transam/xact.c:1832-1837,1895-1902; file:src/backend/access/transam/clog.c:23-25; file:src/backend/access/heap/heapam_visibility.c:29-31〕；假设: 旧版本本来就留在原处（[[D-mvcc-no-overwrite]]），所以回滚不需要 undo（未找到提交或讨论原文）（另见 [[D-mvcc-no-overwrite]]、[[D-wal-redo-only]]）
- D-snapshot-xmin-xmax-xip {[[F2]] [[F4]]} 快照是 (xmin, xmax, 进行中事务列表) → 基础性决策，完整记录见 principles.md 的 [[D-snapshot-xmin-xmax-xip]]
- D-ssi {[[F2]] [[F1]]} SSI 而非 S2PL ← 原始与当前: SI 下读写互不阻塞，S2PL 在高争用下阻塞与死锁代价大；依据 Cahill/Röhm/Fekete 2008 与 Cahill 2009，接受假阳性〔commit:dafaa3efb75; readme:src/backend/storage/lmgr/README-SSI#Credits; readme:src/backend/storage/lmgr/README-SSI#Serializable Isolation Implementation Strategies〕
- D-lock-partition-fastpath {[[F4]]} 锁表分区 + fast-path ← 原始: 单一 LockMgrLock 成为争用瓶颈（8.2 起分区）；DML 弱锁仍在锁管理器 LWLock 上大量争用（9.2 起 fast-path）〔commit:ec0baf949ec; commit:3cba8999b34〕；当前: 同上，且同一关系总落在单个分区〔file:src/backend/storage/lmgr/README:205-211,279-290〕
- D-deadlock-optimistic-wait {[[F4]]} 死锁检测采用乐观等待 ← 原始: 未考证；当前: 让常规授予/释放路径不付死锁检测代价〔file:src/backend/storage/lmgr/README:346-360〕
- D-lazy-xid-vxid {[[F4]]} xid 延迟分配 + VXID ← 原始: 未考证；当前: 只读事务不碰共享 xid 计数，结束时也不必持 ProcArrayLock〔file:src/backend/access/transam/README:193-212,265-270〕
