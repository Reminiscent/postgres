## 设计原因（决策）
- D-wal-redo-only {[[F1]] [[F4]]} 只做 redo 的预写日志 → 基础性决策，完整记录见 principles.md 的 [[D-wal-redo-only]]
- D-wal-self-describing {[[F7]] [[F3]]} WAL 记录格式自描述（标准化块引用）← 原始: 让 pg_rewind、块预取等工具无需理解各 rmgr 即可取得被改的关系与块；同时统一 XLogRegister* API 与 FPI 控制〔commit:2c03216d831〕
- D-custom-rmgr {[[F3]]} rmgr 可注册 ← 原始: 让表/索引 AM 扩展拥有专用 WAL；此前仅有 Generic WAL，不支持逻辑复制〔commit:5c279a6d350〕；当前: 注册只允许在 shared_preload_libraries 阶段（代码未给理由）〔file:src/backend/access/transam/rmgr.c:118〕
- D-full-page-writes {[[F1]] [[F6]]} checkpoint 后首次修改写整页镜像 → 基础性决策，完整记录见 principles.md 的 [[D-full-page-writes]]
- D-checkpoint-spread {[[F4]]} checkpoint 分散写出 ← 原始: 避免 checkpoint I/O 突发；仅后台 checkpoint 节流，shutdown 等仍全速〔commit:867e2c91a0c〕；当前: BufferSync 每写一页经 CheckpointWriteDelay 按 checkpoint_completion_target 节流〔file:src/backend/postmaster/checkpointer.c:777-781〕
- D-hint-wal-checksum {[[F1]]} 开启校验和时 hint 也要 WAL ← 原始: 引入校验和时规定设置 hint 需要在页被弄脏时写 FPW〔commit:96ef3b8ff1c〕；当前: 无 WAL 的 hint 写遇撕裂页会使校验和失败，故干净页首次 hint 插入 XLOG_FPI_FOR_HINT〔file:src/backend/access/transam/README:643-651; file:src/backend/storage/page/README:42-46〕
