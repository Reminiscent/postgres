# I2 可见性

## 1. 不变量

快照决定一个查询看到哪些元组版本；提交、回收（prune/vacuum/截断）、freeze、HOT、multixact、回卷保护和 standby 重放都不得改变任何仍可能存在的快照的判定结果。

适用条件（以下情形有意放松或不适用，各带证据）：
- 非 MVCC 快照（SnapshotAny/Dirty/Self/NonVacuumable/Toast）不按快照语义判定，也不能注册或入栈：file:src/backend/utils/time/snapmgr.c:25-28；toast 行只按"VACUUM 中途失败"判可见：file:src/backend/access/heap/heapam_visibility.c:436-449。
- READ COMMITTED 下 UPDATE/DELETE 遇并发更新时，EvalPlanQual 作用在比语句快照更新的版本上（[[S05.M08]] Inv(1)）。
- TRUNCATE、改写表的 ALTER TABLE、REPACK CONCURRENTLY 不是 MVCC 安全的：用旧快照的并发事务会看到空表：file:doc/src/sgml/mvcc.sgml:1889-1904。
- COPY FREEZE 写入的行其他会话立即可见，文档明说违反 MVCC：file:doc/src/sgml/ref/copy.sgml:276-281（允许条件见 [[S05.M12]] Inv(1)）。
- 非事务写：nextval（[[S06.M18]] Inv(1)）、`vac_update_relstats` 原地覆盖 pg_class 统计列（[[S04.M11]] Inv(2)）、relation map 文件（[[S11.M08]] Inv(2)）。
- 单用户模式不受 xidStopLimit 约束，回卷保护靠操作者（[[S07.M02]] Inv(1)）。
- hot standby 上不支持 SERIALIZABLE，最强是 RR，可能看到不对应任何串行执行的瞬态：file:doc/src/sgml/mvcc.sgml:1907-1915；standby 上快照冲突的处理方式是取消查询，而不是等待（[[S07.M09]] Inv(4)）。
- SSI 不保护系统表、临时表、序列、hint bit 改写等区域：file:src/backend/storage/lmgr/README-SSI:202-206。

## 2. 由什么推出

- [[D-mvcc-no-overwrite]]：旧版本留在原处，由回收方负责只删看不到的。
- [[D-snapshot-xmin-xmax-xip]]：快照是"运行集合"的拷贝，所以提交的可见点就是离开运行集合的那一刻。
- [[D-abort-by-clog]]：中止只需标记，因此"中止"只能用排除法判定。
- [[D-xid-wraparound-freeze]]：32 位 xid 要靠 freeze 和截断界限。
- [[D-ssi]]：可串行化用谓词锁检测，不用读锁。
- [[D-evalplanqual]]：RC 下并发更新改用最新版本重新检查条件。
- [[D-catalog-mvcc-heap]]：catalog 也按 MVCC 快照读。
- [[D-row-lock-in-tuple-header]]：行锁与 multixact 记在 xmax 里，参与可见性判定。
- [[D-logical-decoding-on-wal]]：历史快照，以及 catalog_xmin 的保留。

## 4. 协议

**P1 提交（主库，有 xid）**　file:src/backend/access/transam/xact.c:1544-1560,2441-2446,2483-2490
1. 事务状态机执行 pre-commit：触发延迟触发器、NOTIFY 入队、SSI 提交前检查。
2. RecordTransactionCommit 写 commit WAL（同步提交先 XLogFlush），置 DELAY_CHKPT_IN_COMMIT。
3. 写 clog（异步提交时记下 commit LSN）。
4. ProcArrayEndTransaction：在 ProcArrayLock X 下清 xid、推进 latestCompletedXid、递增 xactCompletionCount。**这一步之后 I2.R1 才成立**：新快照把它视为已提交。
5. sinval 发送 → 释放锁 → 其余清理（之后出错已无法中止）。
- 3 和 4 颠倒：快照会把一个 clog 里还没提交的事务当作不在途，读者按排除法判为中止，并写下错误的 hint bit。读者一侧如果先查 clog 再查在途（违反 I2.R2），会在 3 与 4 之间的窗口把事务误判为已提交（commit:adf6d5dfb20）。
- standby redo 的顺序：clog → KnownAssignedXids → sinval → 释放 AEL（file:src/backend/access/transam/xact.c:6264-6292）。

**P2 PREPARE / COMMIT PREPARED**　file:src/backend/access/transam/twophase.c:1225-1244,1575-1596
1. PREPARE 的 WAL 刷盘 → MarkAsPrepared 建 dummy PGPROC → 锁转给 dummy → ProcArrayClearTransaction 清本后端的 xid，并递增 xactCompletionCount（file:src/backend/storage/ipc/procarray.c:925-937）。
2. COMMIT PREPARED：写 WAL 与 clog → ProcArrayRemove → 回调释放锁。
- 第 1 步不递增计数：本后端在事务内取的快照会在事务外被复用，而那个快照不含该 xid（commit:07f32fcd23a）。

**P3 一轮 lazy vacuum**　file:src/backend/access/heap/vacuumlazy.c:6-13,775-797；file:src/backend/commands/vacuum.c:1985-2009
1. vacuum_get_cutoffs 取 OldestXmin/FreezeLimit/OldestMxact → 读 rel_pages → 取 vistest。
2. 逐页：持 cleanup lock，一次算出全页元组的存活状态，然后 prune + freeze，条件满足时置 VM。
3. 删索引项（阶段 II）→ heap 死项置 UNUSED（阶段 III）。
4. 原地更新 relfrozenxid/relminmxid → 推进 datfrozenxid → 截断 clog/commit_ts/multixact → 更新回卷限值。
- 1 内部颠倒（先读块数，后取 cutoff）：之后追加到表尾的老 xid 不会被扫描，relfrozenxid 被推过它们（commit:31a7e175fd8）。3 颠倒：索引项指向一个已被重用的 TID。4 里"更新限值"放在截断之前：允许分配的 xid 会落进待删的段。

**P4 逻辑槽 xmin 推进**　file:src/backend/replication/logical/logical.c:1963-2035；file:src/backend/replication/slot.c:1232-1300
1. 解码处理 running_xacts 时得到 candidate catalog_xmin（考虑 reorder buffer 里最老的 xmin）。
2. 确认 flush 后把新值写入槽并 ReplicationSlotSave 落盘。
3. 推进 effective_catalog_xmin。
4. ReplicationSlotsComputeRequiredXmin 持 ReplicationSlotControlLock X 聚合各槽，再写入 procarray。
- 2 与 3 颠倒：崩溃后槽回到落盘的旧值，但相应的 catalog 行可能已被删。第 4 步不加锁：并发者用陈旧的聚合值覆盖新值（commit:2a5225b99d7）。

**P5 hot standby 开放与提升**　file:src/backend/access/transam/xlogrecovery.c:2226-2269；file:src/backend/access/transam/xlog.c:6954-6963
1. 由 RUNNING_XACTS（或 shutdown checkpoint 加 StandbyRecoverPreparedTransactions）初始化 KnownAssignedXids 和 pg_subtrans。
2. 到达一致点且快照就绪后，才通知 postmaster 接受只读连接。
3. 提升：RecoverPreparedTransactions → 置 RECOVERY_STATE_DONE → ShutdownRecoveryTransactionEnvironment。
- 第 3 步后两项颠倒：中间窗口里取的快照为空，RecentXmin 会后退（commit:8a4237908c0）。第 1 步漏掉 prepared 事务的子 xid：这些子事务被当作中止（commit:cbfbda78413）。

**P6 并发建索引**：顺序以 [[S11.M12]] Inv(B1) 为准，这里不重复。它在 I2 上的要求是：建索引的后端在 validate 阶段之前必须一直计入视界（I2.R7）。

**P7 导出初始解码快照**　file:src/backend/replication/logical/snapbuild.c:478-508
1. 从 builder 的已提交列表构造快照。
2. 对其中仍在 procarray 里的 xid 执行 XactLockTableWait。
3. 交出 MVCC 快照。
- 跳过第 2 步：一个已写 commit 记录、但还没写 clog 的事务被快照视为已提交；使用者查 clog 未见提交，按排除法判为中止并写下 hint bit（commit:46024c573bc）。

## 5. 并发与失败语义

- **error**：提交从 commit 记录到写 clog 处于临界区，出错升级为 PANIC；ProcArrayEndTransaction 之后的错误已无法中止事务（[[S07.M01]] Contract）。中止时 AtEOXact_Snapshot 释放快照并重置 xmin（[[S07.M06]] Contract）。vacuum 中途出错时 relfrozenxid 保留旧值（卡片标为假设，[[S06.M07]]）。heap 可见性、VM、TOAST 的 error 语义：卡片写"未定义"。
- **crash**：在途 xid 没有 abort 记录，只能按排除法判为中止（I2.R2）；pg_subtrans 启动时清零；hint bit 不写 WAL，丢失后可以重算（卡片标为假设）；逻辑槽只有落盘值生效（I2.R14）；SSI 的谓词锁只在共享内存里，崩溃语义"未定义"（[[S07.M08]]）。
- **cancel**：提交和中止清理期间 HOLD_INTERRUPTS（[[S07.M01]]）；其余模块（M02–M05、heap 可见性、TOAST、表重写）的 cancel 语义：卡片写"未定义"。
- **standby**：运行集合来自 KnownAssignedXids（I2.R15）；回收冲突用取消查询解决（I2.R16）；不分配 xid，VACUUM 和 REPACK 不能执行；不支持 SERIALIZABLE；standby 上的逻辑槽遇到 catalog 冲突时以 RS_INVAL_HORIZON 失效（[[S10.M05]] Contract）。SLRU、heap 可见性、TOAST 的 standby 语义：卡片写"未定义"。

## 8. 校验手段

- amcheck `verify_heapam`（commit:866e24d47db）：查 xmin/xmax 早于 relfrozenxid，以及重定向指针的结构（file:contrib/amcheck/verify_heapam.c:540-589,1182）。查不出：被错删的行、运行时的可见性误判、写错的 hint bit。
- amcheck `bt_index_check(heapallindexed)`（file:contrib/amcheck/verify_nbtree.c:83）：查索引缺 heap 元组（C1 中 CIC 那一型）。查不出 heap 一侧的错删。
- pg_visibility 的 `pg_check_visible`/`pg_check_frozen`（commit:ba0a198fb13；file:contrib/pg_visibility/pg_visibility.c:64-65）：查 VM 位错置（R11、C8）。查不出未置位的漏优化，也不对历史时点判定。
- 运行时报错：freeze 前的检查 "found xmin/xmax from before relfrozenxid"、"cannot freeze committed xmax"（file:src/backend/access/heap/heapam.c:7321,7467,7608）。它们只在事后、恰好被 vacuum 碰到时触发（C2、C3）。
- 断言：init_toast_snapshot 要求存在注册或活跃快照（file:src/backend/access/common/toast_internals.c:731）。只是弱检查，查不出跨事务的 detoast（R18）。
- wal_consistency_checking：能查出 prune/freeze 的 redo 与原操作不一致；但 heap_mask 屏蔽了 hint bit 和 xact infomask（file:src/backend/access/heap/heapam_xlog.c:1379,1399），所以写错的 hint bit 查不出。
- isolation 测试：freeze-the-dead、horizons、predicate-lock-hot-tuple、plpgsql-toast、multiple-cic、prepared-transactions-cic、reindex-concurrently-toast（file:src/test/isolation/specs/horizons.spec 等）。它们只覆盖已知的交错。
- recovery TAP：file:src/test/recovery/t/009_twophase.pl file:src/test/recovery/t/035_standby_logical_decoding.pl file:src/test/recovery/t/048_vacuum_horizon_floor.pl file:src/test/recovery/t/057_snapshot_commit_race.pl 。
- xid 回卷测试模块（commit:e255b646a16；file:src/test/modules/xid_wraparound）。
- **没有机械检查、只靠约定**：R1 的提交顺序与 R2 的读者顺序；R4 递增 xactCompletionCount；R6 视界确为下界（没有断言与实际存活的快照作比较）；R7 的排除条件；R13 的链核对；R16 horizon 的正确性；R20 各 AM 的 SIREAD 义务；R3 构造快照的来源。
